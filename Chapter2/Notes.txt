    2.1 The Predeclared Types
        Go has many types built into the language. 
        These are called predeclared types.
        They are similar to types that are found in other languages:
            Booleans, integers, floats and strings.

        Using these types idiomatically is sometimes a challenge for developers who are transitioning
        from another language. you'll look at these types and see how they work best in Go. Before i review
        the types, lets cover of the concept that apply to all types

        The Zero Value 
            Go like most modern languages, assigns a default zero value to any variable that is declared
            but not assigned a value. Having an explicit zero value makes code clearer and removes
            a source of bugs found in C and C++ programs. 
            There will be zero value for the types.
            Find details on The Go Programming Language Specification.

        Literals
            A Go literal is an explicitly specified number, character, or string. Go programs have four
            common linds of literals. with fifth rare kind of literal

            An Integer literal is a sequence of numbers.
            Integer literal are base 10 by default, but different prefixes are used to indicate
            other bases: Ob for binary (base 2)m Oo fir octal(base 8), or Ox for hexadecimal (base 16).
            you can use either upper or lowercase letters for the prefix. A leading O with no letter after it 
            is another way to represent an octal literal. 
            Do not use it 

            To make it easier to read integer literals, Go allows you to put underscores
            in the middle of your literal. this allows you to group by thousands in base 10 (1_234)

            these underscores have no effect on the value of the number
            the only limitations on underscores are that they can't be at the beginning or end of numbers 
            you can't have them next to each other as well 

            you could put an underscores between every digit 
            for e.g 1_2_3_4
            but dont do it  
            use them to improve readability by breaking up base 10 numbers at the thousands place or to break up 
            binary, octal, or hexadecimal numbers at 1-,2-,or 4-byte boundaries  


            A floating-point literal has a decimal point to indicate the fractional portion of the 
            value. They can also have an exponent specified with the letter e and a positive or negative
            number (such as 6.03e23). You also have the option to write them in hexadecimal by using the 0x prefix.
            and letter p for indicating any exponent (0x12.34p5, which is equal to 582.5 in base 10). 
            as integer literals you can use underscores to format your floating point literals

            A rune literal represents a character and is surrounded by single quotes. Unlike many other languages
            in Go single quotes and double quotes are not interchangeable. Rune literals can be written as single.
            Unicode characters ('a'), 8 bit octal numbers ('\141'), 8-bit hexadecimal numbers ('\x61'),
            16-bit hexadecimal numbers ('\u0061'), or 32 -bit Unicode numbers ('U00000061'). 
            There are also several backslash excaped rune literals, with the most useful ones being newline ('\n'),
            tab ('\t'), single quote ('\''), and backslash ('\\')


            Practically speaking, ue base 10 to represent your integer and floating point literals
            Octal representations are rare, mostly used to represent POSIX permission flag values
            such as Oo777 for rwxrwxrwx. hexadecimal and binary are sometimes used for bit filters
            or networking and infrastructure applications.


            There are two ways to indicate string literals.
            Most of the time, you should use double quotes to create an interpreted string literal
            e.g : 
                "Greetings and Salutations"
            
            These contain zero or more rune literals. they are called interpreted 
            becuase they interpret rune literals numeric and backslash excaped
            into a single characters..
                One rune literal backslash excaped is not legal in a string literal:
                the single quotes excape it is replace by a backslash excape for double quotes

            The only characters that cannot appear in an interpreted string literal are unescaped backslashes,
            unescaped newlines, and unescaped double.
            if you use an interpreted string literal and want your greetings on a different line from  your
            Salutations and want "salutations" to appear in quotes, you need to type 
                "Greetings and\n\"Salutations\"".
            
            If you need to include backslashes, double quotes, or newlines in your string, using 
            a raw string literal is easier. These are delimited with backquotes(`) and can contain
            any character except a backquote. 
            Ther is no excape character in a raw string literal 
            all characters are included as is 
            When using raw string literal, 
            you write a multiline greeting like so:
            `Greetings and
            "Salutations"`

                The Special Type integer types
                    Go does have some special names for integer types. 
                    A byte is an alias for uint8
                    it is legal to assign, compare or perform mathematical operations between a byte and a unit8
                    however, you rarely see uint8 used in Go code; just call it a byte.

                    The second special name is int. On a 32 bit CPU, int is a 32bit signed integer like an int32
                    On must 64 bit cpus, int is a 64 bit signed integer, just like an int64 
                    because int isn't consistent from platform to platform, it is compile time error to assign compare or perform
                    mathematical operations between an int and an int32 
                    or int64 without a type conversion. integer literals default to being of int types.

                    The third special name is uint.
                
                Choosing which integer to use
                    Go provides more integer types than some other languages. Given all these choices
                    you might wonder when you should use each of them. 

                        if you are working with binary file format or network protocol that has an integer of specific sizes
                        or sign, use the corresponding integer type

                        if you are writing a library function that should work with any integer type, take advantages of
                        Go generics support and use a generic type parameter to represent any integer type

                        in all other cases, just use int

                        FormatInt and FormatUint in the strconv package to see the pattern
                    
                Integer operators
                    Go integer support the usual arithmetic operators:
                        +, -, *, /, with % for modules.

                    don't divide an integer with 0.

                    you can combine any of arithmetic operators with = to modify a variable

                    +=, -=, *=, /=, and %=, 
                    for e.g:
                        var x int = 10
                        x *= 2

                    compare integers with 
                        ==, !=, >, >=, <, and <=

                    Go also has bit-manipulation operators for integers
                    bit shift left << and right >>
                    bit mask 
                        & bitwise AND,
                        | bitwise OR,
                        ^ bitwise XOR,
                        &^ bitwise AND not

                    as with arithmetic operators you can also combine all 
                    the bitwise operators with = to modify variable:

                    &=, |=, ^=, &^=, <<=, and >>=


            Floating-point types 
                Go has two floating point types

                type name       largest absolute value                          smallest absolute value
                float32         3.40282346638528859811704183484516925440e+38    1.401298464324817070923729583289916131280e-45
                float64         1.797693134862315708145274237317043567981e+308  4.940656458412465441765687928682213723651e-324

                floating point in Go is similar to floating point math in other languages.
                Go uses the IEEE 754 specification, giving a large range and limited precision.
                picking which floating point type to use is straightforward
                unless you have to be compatible with an existing format, use float64.
                floating-point literals have a default type of float64,
                so always using float64 is the simplest option.
                it also helps mitigate floating point accuracy issues since a float32 has only six or seven deciaml digits of precision.

                You can use all the standard mathematical and comparison operators with floats, except % floating-point
                division has a couple of interesting properties.
                Dividing a none zero floating point variable by 0 returns +Inf or -Inf, depending on the sign of the number
                dividing a floating point variable set to 0 by 0 returns Nan.

                while Go lets you use == and != to compare floats, dont do it. Because of the inexact nature of floats, two floating
                point values might not be equal when you think they shuold be.

                This value sometimes called epsilon depends on your accuracy needs 
                I can't give you a simple rule. if you aren't sure, consult your friendly local mathematician for advice.

                Complex types (you're probably not going to use these)
                    There is one more numeric type and it is pretty unusual. 
                    Go has first class support for complex numbers.

                    There isn't a lot to the complex number support in Go.
                    Go defines two complex number types.

                    complex64 uses float32 values to represent the real and imaginary part,
                    complex128 uses float64 values.

                    var complexNum = complex(20.3, 10.2)
                    Go uses a few rule to determine the type of the value returned by complex
                        if you use untyped constants or literals for both function parameters, you'll 
                        create an untyped complex literal, which has a default type of complex128

                        if both values passed into complex are of float32 type, you'll create a complex64

                        if one value is a float32 and the other value is an untyped constant or literal that can fit
                        within a float32, you'll create a comnplex64

                        otherwise, you'll create a complex128

                        all the standard floating point arithmetic operators work on complex 
                        numbers.
                        you can use 
                            == or != to compare them

                        you can extract the real and imaginary portions of a complex number with 
                        the real and imag built in functions 

                        The math / cmplx package has additional functions for manipulating complex128 values


                        func main() {
                            x := complex(2.5, 3.1)

                            fmt.Println(x / y)
                            fmt.Println(real(x))
                            fmt.Println(imag(x))
                            fmt.Println(cmplx.Abs(x))
                        }

                var Versus :=
                    The most verbose way to declare a variable in Go uses the var keyword, an explicit type 

                    var x int = 10

                    if the type on the righthand side of thee = is the expected type of your variable

                    var x = 10

                    Conversly, if you want to declare a variable and assign it the zero value

                    var x int 

                    you can declare multiple variables at once with var, 
                    var x, y int = 10, 20

                    you can declare all zero values of the same type

                    var x, y int

                    or of different types:

                    var x, y = 10, "hello"
                        
                    there ones more way to use var. if you are declaring multiple variables at once
                    you can wrap them in declaration list

                    var (
                        x int
                        y = 20
                        z int =30
                        d, e = 40, "hello"
                        f, g string
                    )

                    go also supports a short declaration and assignment format.
                    when you are within a function, you can use the
                    := operator to replace a var declarationo that uses type 
                    inference.

                    var x = 10
                    x := 10

                    as with var, you can declare multiple variables at once using :=
                    these two lines both assign 10 to x and "hello" to y

                    var x,y  = 10, "hello"
                    x, y := 10, "hello"

                    the := operator can do one trick that you cannot do with var: it
                    allows you to assign values to existing variables too.

                    x := 10 
                    x, y := 30, "hello"

                    using := has one limitation. 
                    if you are declaring a variable at the package level, 
                    you must use var because := is not legal outside of functions

                    when initializing a variable to its zero value, use var x int.
                    this makes it clear that the zero value is intended

                    when assigning an untyped constant or a literal to a variable and the 
                    default type for the constant or literal isn't the type you want for the variable 
                    use the long var form with the type specidied. 
                    While it is legal to use a type conversion to specify
                    the type of the value and use := to write x := byte(20), it is idiomatic to write var x 
                    byte = 20

                    because := allows you to assign to both new and existing variables, it sometimes creates new
                    variables when you think you are reusing existing ones.
                    Explicitly declare all your new variables with var to make it clear which variables are new,
                    and then use the assignment operator (=) to assign values to both new and old variables

                    you should rarely declare variables outside of functions, in which called
                    the package block

                    package-level variables whose values change are a bad idea. when you have a variable
                    outside of a function, it can be difficult to track the changes made to it,

                    whicha makes it hard to understand how data is flowing
                    through your programs.

                    Avoid declaring variables outside of functions because they complicate data flow analysis

    2.2 Naming Variables and Constants
        There is a difference between Go's rules for naming variables
        and the patterns that Go developers follow when naming theri 
        variables and constants. 
        
        Variable names you should never use : 
            _0 := 0_0
            _1 := 20
            n := 3
            a := "hello" //Unicode u+ff41

            __ := "double underscores"
            fmt.Println(_0)
            fmt.Println(_1)
            fmt.Println(n)
            fmt.Println(a)
            fmt.Println(__)

            using look-alike code points for variable names 

            func main(){
                 a  := 'hello' // Unicode U+FF41
                a := "goodbye" // standard lowercase a (Unicode U+0061)
                fmt.Println(a)
                fmt.Println(a)
            }

            output 
            hello
            goodbye

            underscores are rarely used in variable name 
            idiomatic Go doesn't use snale case 
            names like (index_counter) or (number_tries)
            instead idiomatic Go uses camel case names like
            (indexCounter) or (numberTries)

            go does not follow all upercase letter pattern 

            because Go uses the case of the first letter in the name 
            of a package-level declaration to determine if the item is 
            accessible outside the package 

            The smaller the scope for a variable, 
            the shorter the name that's used for it 
            it is comon in Go to see single letter variable 
            names used as the variable names in a for - range loop
            if you are using standard for loop, i and j are common names
            for index variable 
            there are other idiomatic ways to name variable of common types
            
            Go is stringly typed you don't need to do this to keep track of the underlying
            type. however Go code where the first letter of a type is used as the variable
            name for e.g : i for integers or f for floats.
